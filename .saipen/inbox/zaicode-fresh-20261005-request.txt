REQ-002 — RESPONSIVE COMPOSER

The composer currently cannot fit all enabled controls at some widths.

Make the composer responsive rather than clipping or overlapping controls.

Requirements:
- no control overlap;
- no controls outside the usable client area;
- prompt editor retains useful width;
- primary actions remain directly reachable;
- secondary actions may collapse into a compact overflow/menu at narrow width;
- rows may reflow only when doing so is clearer than horizontal clipping;
- attachments, COLLECT, worker/model controls and send controls must coexist;
- respect sidebar left/right placement and rail/full modes;
- resize live without requiring reload.

Test several practical widths including narrow 1366-class and 1920x1080 layouts.

REQ-003 — PROTRAIL Z-ORDER RECOVERY

ProTrail can occasionally fall behind all other applications and only recover
after restart.

Find the real window ownership/z-order defect.

Do not blindly force permanent always-on-top unless that is the configured
policy.

Required behavior:
- ProTrail obeys its selected topmost/overlay policy;
- activating ZAICODE/ProTrail restores the intended z-order;
- minimize/restore does not strand it behind unrelated windows;
- monitor change does not lose ownership;
- ZAICODE restart must not be the normal recovery mechanism.

Add a deterministic recovery path and regression coverage where technically
possible.

REQ-004 — MAXIMIZE / RESTORE GEOMETRY

The main window can enter a visually "maximized" state while occupying only part
of the available screen/client area.

Investigate:
- Electron maximize/unmaximize state;
- persisted normal bounds;
- monitor/workArea selection;
- DPI scaling;
- renderer viewport resize;
- sidebar/layout cached dimensions;
- maximize after moving between monitors.

Rules:
- maximized means the full current monitor work area;
- never restore stale normal bounds while the native window remains maximized;
- renderer must consume the complete current client rectangle;
- moving between monitors must not preserve impossible old geometry;
- invalid/off-screen persisted bounds must be normalized safely.

Test maximize -> restore -> maximize, restart while maximized, monitor movement,
and common DPI/work-area changes.

- running agent;

- waiting for reset;
- interrupted;
- completed;
- idle.

Completion/terminal exit/worker release must converge the sidebar and session UI
quickly.

App restart must reconcile stale "working" state from real persisted/runtime
truth.

Add regression coverage for:
- normal completion;
- worker crash;
- terminal disappears;
- scheduled continuation;
- app restart after completion;
- tests finish before agent state refresh;
- stale heartbeat.
