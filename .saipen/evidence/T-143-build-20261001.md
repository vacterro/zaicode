## Request, clause by clause

SRC-109 asks for three corrections:

1. remove the thought On/Off switch for models with no explicit thought support, and keep the
   reasoning mode always on ("тупая или умная модель - умная всегда, без вариантов");
2. make the five-hour windows of Antigravity and ZCode work everywhere, start at exactly 0%
   consumption, and run continuously instead of sitting under an "on first use" label;
3. keep the delete-folder dialog text inside the frame.

## 1 -- Thought is always on

The reasoning levels of a model come from the Provider Registry
(`ModelConfig.optionSpecs.reasoningLevel.values`). Every thought control in the UI goes through
one resolver, `resolveModelThoughtOption` in `packages/ui/src/lib/modelThoughtOption.ts`, used by
the composer toolbar, the workflow run-settings popover, the automation editor, the off-peak
editor, the subagents section and the draft workspace defaults. One policy therefore reaches all
of them.

New policy, `packages/shared/src/model-selection.ts`:

- `isThoughtLevelSwitch(values)` -- a list of nothing but on/off markers (`enable`/`disable`,
  `on`/`off`, `true`/`false`, ...) can only ask "dumb model or smart model". ZAICODE never takes
  "dumb", so such a model gets no thought control at all.
- `selectableThoughtLevels(values)` -- an off marker is removed from a graded scale
  (`["none","low","medium","high","xhigh","max"]` becomes `["low"..."max"]`). The menu now only
  answers "how much", never "whether".
- `fixedEnabledReasoningLevel(values)` -- a binary switch resolves to its enabled member.
- `strongestThinkingLevel(values)` -- the strongest level that still means "think".

Applied at:

- `packages/ui/src/lib/modelThoughtOption.ts` -- the guard `isThoughtLevelSwitch` and the level
  list `selectableThoughtLevels`; a current value that is no longer selectable falls back to the
  strongest level rather than staying on a removed one.
- `packages/ui/src/chat-input-toolbar/ThoughtLevelCycleControl.tsx` -- the render guard.
- `packages/ui/src/chat-input-toolbar/thoughtLevelOptions.ts` -- `disable` added to the off
  markers and to the off label map.
- `packages/provider/src/model-selection-config.ts` -- a new selection takes
  `fixedEnabledReasoningLevel(values) ?? strongestThinkingLevel(values)`; `normalizeModelSelection`
  rewrites a stored off level to the strongest thinking level.
- `packages/provider/src/effective-model-selection.ts` -- execution-side pin: whatever an old
  session or a hand-edited config left in the stored options, the request itself never asks a
  thinking model to stop thinking.

## 2 -- Five-hour windows of Antigravity and ZCode

Cause found in SCOUT: `markZaicodeWindowsStartingOnUse` classified a window whose reset sits
roughly a full duration after the read as "starts on first use", and six consumers then excluded
such a window -- it did not count as a real reset, it did not lead the reset title, a schedule
could not wait for it, and the parser dropped rows that carried no consumption fraction.

Change in `packages/shared/src/zaicode-engines.ts`:

- `ZaicodeLimitWindow.rollingFrom` -- the moment ZAICODE first saw the unstarted window. Neither
  Antigravity nor ZCode confirms the start, so ZAICODE runs the window itself: `remainingPercent`
  100, `resetsAt = rollingFrom + durationMinutes`, anchored so the countdown does not restart on
  every sweep. The anchor is carried from the previous sweep by the fourth parameter of
  `markZaicodeWindowsStartingOnUse`, threaded from `probeAccount` in
  `packages/desktop/src/main/zaicodeEngines.ts`.
- `isZaicodeRollingWindow(window)` -- `startsOnUse === true` **and** an anchor. A genuinely
  unstarted window (a snapshot written by an older build) keeps the old behaviour.
- Relaxed for a rolling window: `isZaicodeRealReset`, `zaicodeNextRefillAt`,
  `formatZaicodeWindowReset`, the autostart scheduler (`packages/ui/src/zaicode/ZaicodeResetTimer.tsx`
  carries the flag into the row kind and into `zaicodeNextUsefulReset`, so a running window leads
  the title even at 100%).
- Parser holes that made "exactly 0%" impossible: `parseAntigravityUsage` now keeps a bucket that
  has a reset time but no fraction (Antigravity omits the fraction until the first request), and
  `parseZcodeQuota` keeps a `spent 0 / left 0` row. Both are presented at exactly 0% consumed.
- Window starters extended so the window can really be started:
  `antigravityWindowStartArgs()` (one sandboxed low-effort Flash request),
  `readAntigravityWindowStart()`, `zcodeWindowStartRequest()` (resolves only the vendor-bound
  coding-plan endpoint, refuses credentials/query/fragment and any other origin) and
  `readZcodeWindowStart()` (the response body is never echoed on failure). The rolling keeper
  now covers `antigravity` and `zcode`, not only Claude and Codex.

## 3 -- Delete-folder dialog stays inside the frame

`break-words` (`overflow-wrap: break-word`) does not reduce the min-content width, and
`DialogContent` is a grid, whose items default to `min-width: auto`. A long unbroken folder name
therefore widened the dialog past its own `max-width` and pushed the text out of the frame.

- `packages/ui/src/components/ui/dialog.tsx` -- `DialogHeader` and `DialogFooter` gain `min-w-0`.
- `packages/ui/src/ConfirmDialog.tsx` -- container `overflow-hidden`; title, description, cancel
  and confirm gain `[overflow-wrap:anywhere]` plus `min-w-0`; the cancel button gains
  `whitespace-normal` (it inherited `whitespace-nowrap` from `button.tsx`) and `h-auto min-h-9`
  so a wrapped label is not clipped.

## Tests

New `packages/ui/test/zaicodeT143.test.ts` -- 11 tests. Confirmed red on the pre-change base
(`git stash`, rerun) and green after:

- a bare `["enable","disable"]` list yields no thought control, a real scale keeps its control,
  a scale with an off marker loses the off marker;
- an unstarted 5 h window is anchored at 100% remaining with `resetsAt = readAt + 5 h`, formats
  as `resets in 4h 59m`, keeps the anchor on the next sweep, is no longer "local only";
- a ZCode `0 of 0` row and an Antigravity bucket without a fraction are kept;
- the title timer counts a rolling window down;
- the delete-folder dialog source carries `overflow-hidden`, `[overflow-wrap:anywhere]`,
  `whitespace-normal`/`min-h-9` on the cancel button and `min-w-0` on header and footer.

Four reset tests in `packages/ui/test/zaicodeWave63.test.ts` encoded the superseded SRC-048
contract ("an untouched 5 h window is not a reset"). They were updated to the SRC-109 contract --
a rolling Antigravity 5 h leads the title, a scheduled job waits for a real `dueAt` -- and one
new test keeps the legacy unanchored case asserting `/starts on first use/`, so the old
protection is still covered for windows ZAICODE cannot roll.
