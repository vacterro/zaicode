# T-125 / T-126: presets, import/export and one findable customization folder (handoff)

Recorded 2026-09-29, session claude-code-local-verify, so the work can be picked up later without the chat.
Sources: SRC-088 (T-125), SRC-089 (T-126), plus SRC-087 (T-124, the compact sound list, DONE first).
Nothing below is implemented yet. It is what the operator asked for and what was found in the code.

## What the operator asked (their words are in the two receipts)

1. **Presets in Sound settings, and in every Settings section:** presets, import, export, save. A whole
   system, meant for people to share their setups easily and well.
2. **Custom sounds travel with a preset:** if the user added their own sounds, export and import must
   handle that "smartly" (the preset carries or references the files; an import on another machine must
   still play them or say precisely what is missing).
3. **The sound list updates in real time** when the user adds custom sounds.
4. **One easy-to-find folder** instead of `zcode\packages\ui\src\assets\fastprompter-sounds\`, for
   example `V:\___VAC\__K\__CODE\_AI_STUFF_AGENTIC\_ZAICODE\customization\sounds`, and the same idea for
   the other customization elements that get exported/imported: a "customization / userpref" pack.

## What the code does today (verified 2026-09-29)

- The picker's catalog is BUILD-TIME: `zaicodeSoundCatalog.ts` reads `zaicodeSoundManifest.json`
  (generated by `zcode/scripts/zaicode-sound-manifest.mjs`); playback URLs come from
  `import.meta.glob("../assets/fastprompter-sounds/**/*.{wav,mp3,ogg}")` in `zaicodeAudio.ts:73`. A file
  dropped into that folder is invisible until the manifest is regenerated and the app rebuilt. The
  operator did exactly that: twenty `HORSE*.wav` files sit untracked in
  `packages/ui/src/assets/fastprompter-sounds/` (not part of any T-116..T-124 commit; left untouched).
- "Own file" sounds are per event and live in IndexedDB: `importZaicodeSoundFile(id, file)` in
  `zaicodeSoundEvents.ts:99` stores the file under `custom:<eventId>`; `resolveSoundUrl` (line 65) turns it
  into an object URL; the display name goes to localStorage (`readZaicodeCustomSoundNames`).
  `readBundledZaicodeCustomSound` in `zaicodeSettingsSnapshot.ts:107` is the "release snapshot" fallback,
  so a settings snapshot can already carry custom sound data (`zaicodeSettingsSnapshot.ts:173`).
- A profile bundle system exists: `zaicodeProfileBundles.ts` (`captureZaicodeProfileBundle`,
  `applyZaicodeProfileBundle`, `parseZaicodeProfileBundle`, `ZAICODE_PROFILE_KEYS`) and
  `zaicodeProfiles.ts`. It captures every preference key and never carries live facts. It is the natural
  base for per-section presets; it has no per-section scope, no file import/export UI and no custom-sound
  payload.
- The launcher (`tools/launcher/ZaicodeLauncher.cs`) knows the workspace root and starts the app; the app
  does not get that root as a variable today.

## Proposed design (to be confirmed with the operator before building)

- **Root:** `<workspace root>\customization\` next to `zcode\`. The launcher exports `ZAICODE_ROOT`
  (workspace root) to the app; fallback: walk up from the executable to the folder that holds `zcode\`;
  last fallback `%APPDATA%\ZAICODE\customization`. Created at start with a short README.txt.
  Sub-folders: `sounds\` (drop WAV/MP3/OGG, sub-folders allowed), `presets\` (one file per exported
  preset), later `userpref\` for the whole-pack export.
- **Live list:** the desktop main process watches `customization\sounds\` (fs.watch, debounced,
  re-scan on focus as a safety net) and answers the renderer over IPC with `{ relativePath, seconds }`
  entries plus a "changed" event; the catalog merges them as `custom-file:<relativePath>` entries next to
  the bundled ones (kind from the same `categorizeZaicodeSound`), and playback reads the file through the
  main process (bytes over IPC or a scoped protocol handler), never a raw file path from the renderer.
  The bundled HORSE files should move into that folder or into the manifest, the operator decides.
- **Presets per section:** a preset = `{ schema, section, name, createdAt, keys: {...}, assets: [...] }`,
  scoped to the keys one Settings section owns (reuse `ZAICODE_PROFILE_KEYS` plumbing, add a
  section -> keys map). Buttons on every section: Save as preset, Apply, Rename/Delete, Export to file,
  Import from file (with a preview of what will change and a confirm), Reset to defaults.
- **Assets in a preset (sounds):** export writes the preset JSON and copies every custom sound it uses next
  to it (`<name>.zaicode-preset\` folder or a zip) with a sha256 per file; import copies the files into
  `customization\sounds\` (never overwrites a different file of the same name: suffix + report), maps
  the preset's sound ids to the imported names, and lists anything missing instead of silently falling
  back. Bundled sounds are referenced by id, not copied.
- **Sharing:** a preset is one folder or one zip a person can send; a version field and a
  `requires` list (ZAICODE version, bundled sound pack id) so an import on an older build says why it
  cannot apply.
