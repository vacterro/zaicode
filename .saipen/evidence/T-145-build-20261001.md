## 1. SAIPEN: unreadable is no longer reported as absent

**Defect (from SCOUT, class level).** `SaipenPoller.tick()` caught every read failure and
emitted `null`. `null` is also the answer for "this project has no `.saipen/`", so
`ZaicodeSaipenSidePane` printed *"No .saipen/ memory in this project yet. INIT SAIPEN in the
composer strip creates it."* for a directory that existed and could not be read. There was
nothing on screen that named the real cause and nothing to press.

**Fix.**

- `packages/ui/src/zaicode/zaicodeSaipenModel.ts`: new `readError?: string` on
  `ZaicodeSaipenSnapshot`, plus the pure predicates `isZaicodeSaipenMissingFileError()`
  (`ENOENT` / `ENOTDIR` only) and `describeZaicodeSaipenReadError()`.
- `packages/ui/src/zaicode/zaicodeSaipen.ts`: the catch now branches -- only a genuinely
  missing directory keeps the `null`; anything else emits a snapshot carrying `readError`.
  `SaipenPoller.recheck()` re-reads now, and `useZaicodeSaipenRefresh(workspacePath)` hands
  that to a surface.
- `packages/ui/src/zaicode/ZaicodeSaipenSidePane.tsx`: an unreadable state renders the error
  line plus a **Retry** button, not a sentence telling the user to do something else.

The two helpers live in the model module, not the poller, because that is the module a test
can import without pulling React and the workspace services.

## 2. Help has a curriculum

- New `packages/ui/src/settings/zaicodeHelpOrder.ts`: `ZAICODE_HELP_CURRICULUM`, six chapters
  from `1 · Start here` to `6 · Extras`, with SAIPEGGLE deliberately last, plus
  `resolveZaicodeHelpChapters()` and `zaicodeHelpOrderedTopics()`. Only a **type-only**
  import of `HelpTopic`, so it stays loadable in a plain node test.
- `zaicodeHelpContent.ts`: the `HelpTopic` type, the concatenation of the cards, and the two
  resolved constants. The 33 cards moved to `zaicodeHelpTopicsCore.ts` (17) and
  `zaicodeHelpTopicsAdvanced.ts` (16) -- a size split only, forced by the 400-line lint
  ceiling. Where a card physically lives says nothing about when it is read.
- `ZaicodeHelpSection.tsx`: renders chapters (title + what it covers + its cards), and the
  search filters *within* chapters so a hit still tells the reader which part of the course
  the answer belongs to. The jump chips use the same order.

Coverage is asserted, not hoped for: all 33 ids are filed exactly once, none is lost, and a
card the curriculum does not name lands in `7 · Not filed yet` rather than disappearing.

## 3. Help and reporting leave the building

- `helpMenuActions.ts`: `openZaicodeHelp()` replaces the vendor-docs action; the
  `ZCODE_PRODUCT_DOCS_URL` import is gone. New actions `openGitHubIssue`,
  `openGitHubFeature`, `openRepository` built on `ZAICODE_ISSUE_URL` / `ZAICODE_FEATURE_URL` /
  `ZAICODE_REPO_URL` (`zaicodeBrand.ts`).
- `WorkspaceHelpMenuButton.tsx`: Help (labelled with the existing localized `Help` string,
  since the old "Product docs" promised a page that is no longer opened), Community, the two
  GitHub report lines, the in-app report, Source on GitHub, Export logs, then the existing
  desktop-only block.
- New `.github/ISSUE_TEMPLATE/bug_report.yml`, `feature_request.yml` and `config.yml`. The
  repository had **no** `.github` directory at all, so the template URLs in the brand module
  would have 404'd.
- The Command Center's `product-docs` command opens ZAICODE Help in ZAICODE product mode and
  keeps the vendor URL for upstream ZCode. `QuickPickCommand` gained an optional literal
  `title` for that single branded line; `CommandCenterDialog` prefers it.

## 4. About is ZAICODE's

- `aboutWindow.ts` accepts `logoDataUri`, `tagline` and `repository`. With a logo it draws
  `<img class="app-logo-img">`; without one it keeps the vector mark, so a missing file never
  produces a blank icon. Text still goes through `escapeHtml`.
- `about.ts` reads the PNG and inlines it as a data URI (the About window is sandboxed with
  `img-src data:`), from `process.resourcesPath/zaicode-logo-128.png` when packaged and
  `build/zaicode-logo-128.png` in development. Copyright credits vacterro; the tagline and the
  repository line are ZAICODE-only.
- The card grew 280 -> 308 px and the window 312 -> 340 px, keeping the 32 px breathing room
  the window size exists for, so the two new lines fit inside the frame.
- `packages/desktop/build/zaicode-logo-128.png` is a copy of
  `packages/ui/src/assets/zaicode-logo-128.png`, and `electron-builder.config.js` copies it
  into `extraResources`. Without that entry `process.resourcesPath` finds nothing in a
  packaged build and About silently falls back to the vendor mark.
