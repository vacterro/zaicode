# T-225 / SRC-155: composer overflow + bevels on list rows

## Scope

  fit, unacceptable UI.

  cascade math, visuals stay MANUAL_PENDING on the operator checklist below.

## Root causes (proven in code)

### R1 composer: the promised last-resort wrap does not exist
- `ChatPromptEditor.tsx` toolbar root: `group/toolbar flex items-end gap-3`
  (nowrap). Trailing cluster: `ml-auto flex shrink-0 ...` (never shrinks).
- The composer shell is `overflow-hidden`. Past the last collapse rung the
  irreducible trailing floor (model icon + goal + retry + working-for + send,
  all icon-size, none collapsible by design) overflows the nowrap row and the
  shell clips the buttons.
- `useComposerToolbarFit.ts` even documents the missing fallback: "the whole
  row wraps via CSS" -- no such CSS existed on the root row.
- Fix: root row is now `group/toolbar flex flex-wrap items-end gap-3`.
  Trailing keeps `ml-auto justify-end`, so on a narrow row it drops to its own
  right-aligned line instead of clipping. Leading/trailing keep inner wrap.

### R2 bevels: the rows toggle dies in a specificity tie (non-classic styles)
- Wiring intact: toggle -> `bevelRows` -> `zaicode-bevel-rows` class on <html>;
  ROWS selectors match rendered rows (`workspace-item-*` div, `task-item-*` li);
  palette bevel tokens exist (Golden Default #75663D / #100e08).
- `ZAICODE_PRESENTATION_CSS` (injected AFTER the bevel CSS in the same style
  element) kills shadows for `:is(button,[role="button"],...)` under any
  non-classic presentation at specificity (0,3,1). The workspace-row bevel
  (`div[role="button"]`, `html.zaicode-bevels.zaicode-bevel-rows
  [data-testid^="workspace-item-"]`) is also (0,3,1): tie, later source wins,
  rows go flat while the toggle claims ON.
- Fix (`zaicodeBevels.ts`): row rules now scope on
  `html.zaicode-bevels.zaicode-bevel-rows[data-zaicode-style]` -> (0,4,1),
  so the explicit rows toggle outranks the preset. `[data-zaicode-style]` is
  always set exactly when the bevel classes can be (product mode), same match
  set under Classic. Buttons/fields keep preset behavior (kill-rule untouched).
