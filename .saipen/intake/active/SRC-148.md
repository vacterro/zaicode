P0 — ROUTING CONTINUITY / LOST-WORK PREVENTION

REQ-002
A dead or crashed user-local 9router must never leave an autonomous ZAICODE run
retrying a nonexistent endpoint for hours.

Build a health-aware fail-open routing supervisor.

Required behavior:

1. Detect that the configured user-local 9router process/service/API is actually
   unavailable.

2. Distinguish:
   - router process unavailable;
   - router API unhealthy;
   - temporary connection failure;
   - provider/model failure behind a healthy router;
   - subscription quota exhaustion.

   Do not collapse these into one generic inference failure.

3. For a dead/unavailable user-local 9router:
   - attempt silent recovery;
   - make up to 10 bounded restart/reconnect attempts;
   - health-check after every attempt;
   - use bounded backoff;
   - do not create overlapping restart processes;
   - do not spin an infinite retry loop.

4. If the user router is still unhealthy after the recovery budget:
   fail open to ZAICODE's usable internal fallback path.

5. Preserve:
   - project;
   - session;
   - objective;
   - scheduler ownership;
   - pending continuation state;
   - current task intent.

   Fallback must continue the same work, not create an unrelated replacement task.

6. While running on fallback:
   periodically probe the preferred local router at a sane low frequency.

7. When the local router becomes healthy again:
   return to it safely at a continuation boundary.

   Do not interrupt a healthy in-flight inference merely because the preferred
   router came back.

8. Add cooldown/hysteresis so a flapping router cannot bounce the workload
   endlessly between preferred and fallback routes.

9. Persist enough supervisor state that a ZAICODE restart does not forget:
   - router failure state;
   - retry budget;
   - fallback activation;
   - pending recovery.

10. Surface truthful status to the operator:
    preferred router unavailable / recovering / fallback active / restored.

11. A dead router must never be reported as working merely because retry timers
    are still firing.

12. Add regression coverage for:
    - router process disappears;
    - API becomes unreachable;
    - restart succeeds on an intermediate attempt;
    - all 10 attempts fail;
    - fallback succeeds;
    - ZAICODE restarts during fallback;
    - local router later recovers;
    - router flaps repeatedly;
    - fallback itself is unavailable;
    - quota exhaustion behind a healthy router is not mistaken for router death.
