# ZAICODE UI

## Product Purpose

ZAICODE is a desktop-first operator workspace for running and supervising coding agents through one graphical interface.

## Account Model

ZAICODE has no mandatory application account.

Cloud authentication is provider-specific.

Workspace access, agent management, queue management, routing configuration, local-provider configuration, and application settings remain available without a Z.ai account.

Z.ai is an optional external provider and has no privileged product-level status inside ZAICODE.

## Execution Architecture

Document the intended conceptual path:

ZAICODE UI
→ Agent / Work Queue
→ SAIFREN
→ SAIRoute
→ 9router
→ Provider / Model
→ Runtime
→ Result

Clearly mark unimplemented layers as planned integration boundaries rather than pretending they already exist.

## Main Workspace

- Project/Workspace navigation;
- Agent Roster;
- Work Queue;
- Active Runs;
- Inspector;
- Result/Event surface.

## Agent Roster

- role;
- state;
- resolved provider;
- resolved model;

## Modal Policy

Prefer integrated panes, tabs, inline editors, searchable lists, segmented controls, and direct selections.

Avoid unnecessary chains of modal dialogs and combobox-heavy configuration.

## Persistence Ownership

Every UI state must be classified as:
- runtime-authoritative;
- persisted product configuration;
- UI preference;
- derived presentation state.

React components must not become authoritative queue/session storage.

## Startup Behavior

Fresh ZAICODE installation:
1. starts without cloud login;
2. opens the product shell;
3. allows workspace access;
4. allows configuration;
5. truthfully reports missing execution routes.

## Non-Goals

- distributed schedulers;
- recursive autonomous swarms;
- arbitrary DAG editor;
- new provider stack;
- replacement terminal;
- unrelated upstream redesign;
- mandatory cloud identity.
